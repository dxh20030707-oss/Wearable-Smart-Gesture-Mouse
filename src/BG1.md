# 🚀 ESP32-C3 智能飞鼠/触控一体鼠标项目阶段性总结报告

本报告针对当前开发的基于 **ESP32-C3** 主控的软硬件一体化智能外设（飞鼠 / 触控一体化鼠标）进行系统性的总结与梳理。本系统利用 PlatformIO 框架开发，通过复用 GPIO 架构，将惯性传感器（MPU6050）、电容触控屏（FT6336U）、OLED 屏幕及正交编码器（EC11）有机结合，实现核心交互模式的平滑切换。

---

## 📌 一、 架构现状梳理

### 1. 引脚分配总览 (GPIO 复用架构)
系统通过核心模式切换键（GPIO 10）动态切换中断与引脚模式，实现了有限引脚的高效复用：

| 物理引脚 | 核心公共通道 | 模式 1：飞鼠正常模式 | 模式 1：飞鼠断控模式 | 模式 2：电容触控模式 |
| :--- | :--- | :--- | :--- | :--- |
| **GPIO 0** | - | 鼠标左键输入 | 编码器 A 相 (TIM-CH1) | 编码器 A相 (TIM-CH1) |
| **GPIO 1** | - | 鼠标右键输入 | 编码器 B 相 (TIM-CH2) | 编码器 B 相 (TIM-CH2) |
| **GPIO 2** | - | 断开飞鼠控制按键 | 恢复飞鼠控制按键 | 触控芯片中断 (INT) |
| **GPIO 3** | - | 鼠标灵敏度环形调节键 | 滚动灵敏度环形调节键 | 触控芯片复位 (RST) |
| **GPIO 8** | I2C SDA (公共总线) | MPU6050 / OLED 通讯 | MPU6050 / OLED 通讯 | FT6336U / OLED 通讯 |
| **GPIO 9** | I2C SCL (公共总线) | MPU6050 / OLED 通讯 | MPU6050 / OLED 通讯 | FT6336U / OLED 通讯 |
| **GPIO 10**| 模式切换核心按键 | 飞鼠 $\rightarrow$ 触控屏 | 飞鼠 $\rightarrow$ 触控屏 | 触控屏 $\rightarrow$ 飞鼠 |

---

### 2. 代码分布与文件明细

目前整个项目的代码划分为“主控调度”、“硬件驱动”以及“手势/模式行为”三大层次：

*   **`include/config.h`**
    *   **核心功能**：全局引脚宏定义、系统常量（如滤波器系数、死区阈值）、跨文件全局共享变量声明（如 `is_ctrl_pressed`）。
*   **`src/main.cpp`**
    *   **核心功能**：系统总入口。初始化 I2C 总线与底层蓝牙服务，配置信号发射强度；构建 `loop()` 核心状态机，驱动核心切换按键（GPIO 10）的去抖扫描，执行模式 1 与模式 2 的时序分流调度。
*   **`src/mpu6050_driver.cpp` / `mpu6050_driver.h`**
    *   **核心功能**：MPU6050 传感器的寄存器级初始化及 I2C 原始数据流读取驱动。
*   **`src/display_mode.cpp` / `display_mode.h`**
    *   **核心功能**：OLED 渲染引擎。根据当前处于的系统模式，动态绘制光标坐标相对跳变、当前灵敏度百分比、以及蓝牙连接状态等可视化测试信息。
*   **`src/mouse_mode.cpp` / `mouse_mode.h`**
    *   **核心功能**：模式 1（飞鼠）行为层。包含开机静态零偏自动校准、一阶低通滤波消噪算法、整型截断死区控制；实现正常模式下按键控左右键、断控模式下物理寄存器级别直读正交编码器数据转换为蓝牙滚轮信号、以及基于 GPIO 3 的长按/短按自适应灵敏度环形调节算法。
*   **`src/touch_mode.cpp` / `touch_mode.h`**
    *   **核心功能**：模式 2（触控）行为层。FT6336U 电容屏双指数据 I2C 解析驱动；正交编码器中断捕获；处理单指单击/双击/拖拽、双指捏合缩放（联动 `is_ctrl_pressed` 条件分流器）、双指按住长距离滑动自适应定时器自动滚动算法，以及双指移动锁防误触右击机制。

### 3. 总体实现思路
本项目的核心思路是基于 **“时间片节流 + 硬件状态机分流”**。
通过一个主 `loop()` 定时器调度，将蓝牙包发送窗口严格限制在 `12ms ~ 15ms` 之间，既保证了 NimBLE 后台线程不被单核 CPU 饿死，又确保了 HID 报告的高刷新率。
*   **在飞鼠模式下**，将陀螺仪的连续浮点运算平滑化，并在输出最末端通过整型死区隔离 $-1$ 像素蠕动噪声；当进入断控状态，引脚瞬间重构为正交计数器，接管页面滚动。
*   **在触控模式下**，通过升级为“位置/速度时钟触发机制”，只要手指滑动跨越初始判定线且未抬起，单片机纯靠内部定时时钟源源不断向 PC 发送滚轮报告，从机制上解决了断续卡顿问题。

## ⚠️ 二、 现有代码缺失及潜在缺陷检查

根据先前的提词历史以及当前的运行状态，评估出目前工程中**缺失的机制或隐含的设计漏洞**包括：

1.  **模式 1 断控状态下灵敏度按键引脚复用冲突（硬伤）**
    *   在飞鼠断控模式下，要求 GPIO 3 作为“控制滚动的灵敏度调节”。但由于断控模式是通过 `updateLockKeyLogic()` 在 `mouse_mode.cpp` 内部直接就地拦截的，引脚中断和 `pinMode` 并没有真正解绑重新初始化。这会导致在断控模式下按下 GPIO 3，可能同时触发了鼠标的灵敏度改变和滚动的灵敏度改变，代码层缺乏彻底的逻辑状态隔离。
2.  **正交编码器（EC11）极性反向与偶尔检测出反向错误（噪声）**
    *   飞鼠断控模式和模式 2 都用到了编码器。目前模式 1 断控下采用的是寄存器直读法，模式 2 采用的是中断法。硬件上由于没有加入电容滤波，在编码器转动速度极慢或停在临界点时，机械弹片的抖动会导致物理寄存器状态频繁跳变，产生偶尔反向的检测错误。现有代码缺少软件状态机防抖约束（如二级判定或正交格雷码状态机验证）。
3.  **模式切换键（GPIO 10）在特定状态下无法退出的死锁风险**
    *   当系统切换模式时，会调用 `switchSystemMode` 来 `detachInterrupt`（注销中断）。如果此时触控芯片正处于按下状态且中断引脚（GPIO 2）被强行拉低，退出模式 2 并回到模式 1 的一瞬间，GPIO 2 可能会因为残留的电平状态立刻误触发飞鼠模式的“断开控制”功能，导致用户感觉“GPIOA10 切换不回模式 2”或切过去立刻被卡死。
4.  **OLED 坐标渲染数据未完全打通**
    *   触控屏计算出的绝对坐标相对跳变，虽然在内部做了解码，但与 `display_mode.cpp` 之间的全局共享变量没有形成标准接口，导致 OLED 刷新时可能出现部分模式下的坐标变换无法显示。

## 🔮 三、 未来优化计划与发展建议

在后续的迭代中，我们将针对触控、飞鼠及复合交互功能进行深度打磨。以下是针对未来计划给出的系统性优化建议：

### 1. 触控屏缩放与右键功能优化建议
*   **动态锚点中心缩放机制**：目前双指捏合缩放（利用双指距离变化 `distDelta`）是固定发送滚轮信号。可以考虑加入“动态中心点锚定”，即计算双指当前的几何中心坐标 $(X_c, Y_c)$。虽然单片机不能改变电脑光标位置，但可以通过判断中心点在触控屏左侧还是右侧，来动态调整缩放包发送的频率，从而使 CAD 或 EDA 绘图软件的缩放体验更符合直觉。
*   **基于“接触面积/压感”的右键二次判定**：双指轻击触发右键目前全靠时间差判定（$<300\text{ms}$）。由于电容屏在手指抬起时电荷会发生物理扩散，建议引入双指间距的突变率过滤。如果双指抬起时两点距离瞬间大范围发散，说明是滑动的收尾动作而非轻击，应直接剔除，从而让右键的判定更加坚固。

### 2. 飞鼠滚动功能优化建议
*   **带物理惯性的滚轮模拟（Flywheel Effect）**：飞鼠在断控模式下通过旋钮滚动页面，目前是转一格动一格。建议引入“软件虚拟飞轮”算法。当检测到正交编码器在极短时间内连续触发了数次（说明用户在快速甩动旋钮），在旋钮停止转动后，单片机内部继续以指数衰减的频率自动发送几帧微小的滚轮包，模拟高档鼠标“无阻尼滚轮”的物理惯性滑行效果，这会让浏览长网页非常解压和顺畅。
*   **动态速度阶梯**：不再使用单一的灵敏度比例相乘，而是根据编码器转动的角速度（单位时间内触发的中断数），自动在内部切入倍率惩罚或奖励机制。慢速转动时一格对应一像素，快速转动时一格对应半页，实现精准度与速度的兼得。

### 3. 系统级协同建议
*   **统一的全局事件总线（Event Bus）**：建议未来将引脚状态的改变（长按、短按、双击）抽象为独立的事件，而不是打散在各个模块里用 `digitalRead` 互抠。这能从根本上消除断联模式下 EC11 滚动与灵敏度调节打架、按键按住无法松开等因为状态机耦合引起的历史顽疾。
